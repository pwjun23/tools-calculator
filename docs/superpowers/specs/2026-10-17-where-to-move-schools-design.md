# 이사 어디 — 학교까지 등하원 어림값 설계

3단계(직장 통근, `2026-10-16-where-to-move-commute-design.md`)에 이어서, 아이들 학교를 여러 곳 넣고 단지에서 학교까지 걸리는 어림 시간을 보여 주고 그 값으로 거른다.

## 목표
- 설정에서 학교를 최대 4곳 넣는다. 학교마다 이름과 보여 줄 수단(🚶 도보, 🚗 자가용, 🚌 통학차량, 🚇 대중교통, 여러 개)을 고른다.
- 거래 카드에 장소마다 한 줄: `첫째 ○○초 0.6km · 🚶 약 10~15분 · 🚌 약 5~10분`.
- 통근 필터를 장소별 묶음으로 넓힌다.

## 범위 밖
- 학군·배정 정보, 통학차량 실제 노선·타는 곳, 카톡 알림 변경, 예산 판정 반영.
- 카카오 결과를 브라우저(로컬스토리지)에 저장하는 것. 카카오 약관은 저장 위치와 상관없이 결과 저장을 막는다. 좌표 API 승인 뒤 DB 저장으로 해결한다.

## 설정 (`lib/whereToMove/settings.ts`)
- `settings.schools`: `{ label: string; address: string; lat?: number; lng?: number; modes: SchoolMode[] }[]`, 0~4개(`MAX_SCHOOLS = 4`), 기본값 `[]`. 예전 설정(필드 없음)은 `[]`로 읽는다.
  - `SchoolMode = "walk" | "car" | "shuttle" | "transit"`, `modes`는 1개 이상, 중복 없음.
  - `label` 1~20자, `address` 1~200자, 좌표 규칙은 직장과 같다(둘 다 있거나 둘 다 없음, 한국 범위).
- 직장(`workplaces`)은 그대로 둔다.
- 설정 화면 "학교" 섹션: 직장과 같은 검색(도로명주소 검색 API, 학교 이름·주소) → 후보 선택 → 좌표(좌표 API, 승인 전에는 좌표 없이) → 목록에 추가. 학교마다 이름 입력, 수단 체크박스, 삭제 버튼. 4곳이면 검색 칸을 숨긴다. 새 학교의 기본 이름은 검색 결과의 건물 이름(없으면 `학교`), 기본 수단은 도보.
- 검색·좌표 서버 액션은 직장과 같은 것을 쓴다.

## 어림값 (`lib/whereToMove/commute.ts`)
- 상수 `COMMUTE_ASSUMPTIONS`에 추가:
  - `walk: { kmh: [3, 4] }` — 아이 걸음. 도로 거리 ÷ 4 ~ ÷ 3.
  - `shuttle: { factor: [1.5, 2] }` — 자가용 범위의 최솟값 × 1.5 ~ 최댓값 × 2(여러 곳을 들름).
- `estimateModes(km, modes)` → `{ km, times: Partial<Record<TripMode, [number, number]>> }`, `TripMode = "walk" | "car" | "shuttle" | "transit"`. 5분 단위 반올림, 최솟값 최소 5분, 최솟값 ≤ 최댓값.
  - car·transit 은 기존 `estimateCommute`와 같은 값이다.
- 직장 줄도 같은 함수로 만든다(수단 `["transit", "car"]`).
- ⓘ 설명에 도보·통학차량 문장을 더한다:
  - "도보는 아이 걸음으로 시속 3~4km로 봤습니다. 횡단보도·육교는 반영하지 않았습니다."
  - "통학차량은 노선과 타는 곳을 알 수 없어 자가용 시간의 1.5~2배로 잡았습니다. 타는 곳까지 걷는 시간은 빠져 있습니다."
  - 첫 문장은 "단지와 직장·학교 사이의 직선거리로"로 바꾼다.

## 목록 (`app/whereToMove/page.tsx`, `DealBoard.tsx`)
- 장소 목록 `places = [직장?, ...학교]`, 각 장소는 `{ id: "w" | "s0".."s3", label, lat, lng, modes }`. 좌표가 없는 장소는 직장과 같이 임시(WTM_KAKAO_LIVE)면 주소로 그때그때 구하고, 못 구하면 그 장소를 뺀다.
- 거래마다 `trips: { id, km, times }[] | null`(단지 좌표 없으면 null)과 `site` 상태, 단지 좌표를 붙인다. 기존 `commute` 필드는 `trips`로 바꾼다.
- 카드: 장소마다 한 줄 `{label} {km} · 🚶 약 a~b분 · …`(수단 순서 walk, shuttle, car, transit). ⓘ는 첫 줄 끝에 하나만.
  - 좌표 없음: `직장·학교까지 거리: 위치 확인 중|위치 확인 안 됨` 한 줄.
- 길찾기 링크: 직장은 지금처럼 🚇·🚗. 학교는 `{label} 길찾기` 하나 — 도보를 골랐으면 `walk`, 아니면 `car`. `kakaoRouteUrl`이 `walk`를 받는다.
- 장소가 하나도 없으면 줄·링크·필터를 모두 숨긴다.

## 필터
- 한 칸(`select`)에 `optgroup`으로 장소별 묶음:
  - `전체`
  - 직장: `🚇 30·45·60·90·120분`, `🚗 30·45·60·90·120분` (지금과 같음)
  - 학교마다: 고른 수단마다 `10·15·20·30분`
- 값 형식 `{id}:{mode}:{max}`(예 `s0:walk:15`). 장소가 없어졌거나 형식이 틀리면 `전체`.
- 거르기: 그 장소·수단 어림 범위의 최솟값 ≤ max 이면 보인다. `trips`가 null 이면 숨기지 않는다.

## 오류 처리
- 직장과 같다. 검색·좌표 실패는 섹션 안 문장, 카카오 실시간 실패는 '위치 확인 중'.

## 테스트 (가상 값)
- 설정: schools 0·4개 허용, 5개 거부, modes 빈 배열·중복·모르는 값 거부, 좌표 하나만 거부, 예전 설정 → `[]`.
- `estimateModes`: 도보 0.6km·2km, 통학차량 = 자가용 × 1.5~2, car·transit 이 `estimateCommute`와 같음, 최소 5분, 고른 수단만 나옴.
- 필터 선택지: 장소·수단별 묶음과 값, 직장 시간 30~120, 학교 시간 10~30, 값 해석(없는 장소·틀린 형식 → 전체), 최솟값 기준, null 유지.
- `kakaoRouteUrl("walk", …)`.
