# 이사 어디 — 3단계 직장까지 통근 어림값 설계

2단계(지역 설정, `2026-10-16-where-to-move-regions-design.md`) 다음 단계다. 사용자가 직장 주소를 넣으면 거래 카드마다 직장까지의 직선거리와 대중교통·자가용 **예상 시간 범위**를 보여 주고, 그 값으로 거른다.

## 목표
- 설정 화면에서 직장 주소를 검색해 고른다. 지금은 1곳이다.
- 거래 카드에 `직장 14km · 🚇 약 50~75분 · 🚗 약 30~40분 ⓘ`를 보여 준다.
- ⓘ를 누르면 이 값이 직선거리로 추정한 어림값이라는 설명이 펼쳐진다.
- 카드에 카카오맵 길찾기 링크(대중교통·자동차)를 둔다. 정확한 경로·시간·요금은 거기서 본다.
- 목록에 "통근 [대중교통|자가용] [N분] 이내" 필터를 둔다.

## 범위 밖
- 비용(대중교통 요금, 유류비, 통행료). 경로를 모르면 통행료를 알 수 없어 시간만 보여 주기로 했다.
- 실제 길찾기 API(카카오모빌리티, ODsay, TMAP). 결과 저장이 약관상 막혀 있고, 공개 서비스에는 제휴 계약이 필요하다.
- 직장 2곳 이상, 카톡 알림 변경, 예산 판정 반영, 공개(4단계).

## 왜 이렇게 하나 (조사 결과, 2026-10-16)
- 카카오모빌리티 길찾기: 저장 불가(데브톡 담당자 답변), 상업 이용은 무료 범위 안에서도 제휴 계약 필요.
- ODsay: Basic 하루 30회, 비상업만, 사전 동의 없는 결과 저장 금지(약관 4.5.10).
- TMAP 대중교통: 무료 하루 10건, 저장 뒤 24시간 넘게 사용 금지.
- 카카오 로컬·네이버·브이월드 지오코딩: 결과 저장 금지.
- 행정안전부 도로명주소 검색·좌표 API: 무료, 공공데이터포털 표기 "이용허락범위 제한 없음". **좌표는 이것으로만 구해 저장한다.**
- 카카오맵 URL 길찾기 링크(`https://map.kakao.com/link/by/{traffic|car}/이름,위도,경도/이름,위도,경도`)는 API 호출이 아니라 링크라 저장 문제가 없다.

## 주소 → 좌표 (`lib/whereToMove/juso.ts`)
- 키: `JUSO_SEARCH_KEY`(도로명주소 검색 API), `JUSO_COORD_KEY`(좌표제공 API). business.juso.go.kr에서 따로 받는다. 개발 키는 90일 만료이고 운영 키는 운영 도메인 등록이 필요하다.
- 순서: 검색 API에 키워드를 넣어 첫 결과의 행정구역코드·도로명코드·지하 여부·건물 본번·부번을 얻는다 → 좌표 API로 주출입구 좌표를 얻는다.
- 좌표 API는 UTM-K(EPSG:5179) 좌표를 준다. 위경도(WGS84)로 바꿔 저장한다. 변환은 순수 함수 `utmkToWgs84`이고 알려진 지점으로 테스트한다(오차 10m 이내).
- 정확한 요청 파라미터·응답 필드 이름은 계획 단계에서 실제 키로 한 번 호출해 확인하고 계획에 적는다.
- 키는 오류 메시지와 로그에서 가린다.

## 단지 좌표 (`wtm_complexes`)
- 새 표:
  `wtm_complexes(sgg_cd text, dong text, apt text, apt_seq text, road_addr text, jibun_addr text, lat double, lng double, status text, updated_at timestamptz, primary key(sgg_cd, dong, apt))`
  - 키는 거래 표와 같은 `(sgg_cd, dong, apt)`라 거래 표를 바꾸지 않고 붙일 수 있다. `dong`은 거래의 `umdNm` 그대로다(`양촌읍 양곡리`처럼 리까지).
  - `status`: `pending`(아직), `ok`(좌표 있음), `notfound`(주소를 찾지 못함).
- 국토부 응답에서 단지 정보를 꺼낸다. 매매: `roadNm`·`roadNmBonbun`·`roadNmBubun`, 전월세: `roadnm`(예: `감정로 64`), 둘 다 `jibun`·`aptSeq`. 주소 문자열은 `시·도 이름 + 시·군·구 이름 + 도로명 + 본번(-부번)`, 없으면 `시·도 + 시·군·구 + 동 + 지번`이다. 시·도·시·군·구 이름은 `regions.json`에서 찾는다.
- 수집할 때 새 단지를 `pending`으로 넣는다(이미 있으면 그대로 둔다). 도로명 주소가 비어 있던 행에 나중에 값이 오면 채운다.
- 좌표 채우기 `geocodePending(limit)`: `pending` 단지를 도로명 주소로 먼저, 실패하면 지번 주소로 찾는다. 둘 다 결과가 없으면 `notfound`. 네트워크·키 오류는 `pending`으로 두어 다음에 다시 한다. 한 단지가 실패해도 나머지는 계속한다.
- 언제:
  - 매일 06시 수집 Cron 끝에서 1회 최대 100단지.
  - 설정 저장 뒤 새 지역 수집(`after()`) 끝에서도 같은 함수를 돈다.
  - 기존 단지는 일회성 스크립트 `scripts/where-to-move/backfill-complexes.ts`가 지난 12개월 응답에서 단지를 넣고 좌표까지 채운다.
- `notfound`는 자동으로 다시 시도하지 않는다. 스크립트로 `pending`으로 되돌릴 수 있다.

## 설정
- `settings.workplaces`: `{ label: string; address: string; lat: number; lng: number }[]`, 0~1개. 기본값 `[]`. 예전 설정(필드 없음)은 `[]`로 읽는다.
- `label`은 사용자가 붙이는 이름(기본 `직장`), `address`는 고른 도로명 주소다.
- 설정 화면 "직장" 섹션:
  - 주소 키워드 입력 → "검색" → 서버 액션이 검색 API를 불러 후보 최대 10개를 보여 준다 → 하나를 고른다.
  - 고른 후보로 좌표 API를 불러 좌표를 정한 뒤 폼에 넣는다. 저장은 기존 저장 버튼으로 한다.
  - "삭제" 버튼으로 직장을 비운다.
  - 검색·좌표 오류는 섹션 안에 문장으로 보인다.
- 저장 액션은 좌표가 한국 범위(위도 33~39, 경도 124~132) 안인지 검사한다.
- 직장 주소는 개인 값이라 DB에만 있다. 테스트·문서는 가상 주소만 쓴다.

## 어림값 (`lib/whereToMove/commute.ts`, 순수 함수)
- `straightKm(a, b)`: 하버사인 거리(km).
- `estimateCommute(km)` → `{ km, transit: [min, max], car: [min, max] }`, 분 단위 정수(5분 단위로 반올림).
  - 도로 거리 어림 `road = km × 1.3`.
  - 자가용: `road ÷ 40km/h + 5분` ~ `road ÷ 25km/h + 5분`.
  - 대중교통: `road ÷ 25km/h + 10분` ~ `road ÷ 15km/h + 20분`.
  - 상수는 파일 맨 위 한 곳(`COMMUTE_ASSUMPTIONS`)에 둔다. ⓘ 설명 문구도 이 상수에서 만든다.
- 1km 미만은 `직장 1km 미만`으로 보여 주고 시간은 그대로 계산한다.

## 목록 화면
- 서버(page)에서 거래의 `(sgg_cd, dong, apt)`로 단지 좌표를 한 번에 읽어, 직장이 있으면 거래마다 `commute: { km, transit, car } | null`과 단지 좌표를 붙인다. 좌표가 없으면 `commute: null`이다.
- 카드:
  - 통근 줄: `직장 14km · 🚇 약 50~75분 · 🚗 약 30~40분` + 작은 ⓘ 버튼.
  - 좌표 없음: `직장까지 거리: 위치 확인 안 됨` (status가 `pending`이면 `위치 확인 중`).
  - 링크: `🚇 길찾기`, `🚗 길찾기` → 카카오맵 `link/by/traffic|car/{단지명},{위도},{경도}/{직장 label},{위도},{경도}`, 새 창. 이름의 쉼표·슬래시는 지운다.
- ⓘ 설명(누르면 펼침, 다시 누르면 닫힘; 버튼에 `aria-expanded`). 문구:
  - "이 시간은 길찾기 결과가 아닙니다. 단지와 직장 사이의 **직선거리**로 추정한 어림값입니다."
  - "계산: 실제 길은 직선보다 길어서 직선거리 × 1.3을 도로 거리로 봅니다. 자가용은 시속 25~40km에 5분, 대중교통은 시속 15~25km에 걷기·기다리기 10~20분을 더했습니다."
  - "반영 안 된 것: 실제 노선과 환승, 배차 간격, 출퇴근 혼잡(예: 김포골드라인), 신호·정체, 주차."
  - "강·바다·철길을 돌아가야 하거나 다리·IC가 먼 곳은 실제와 크게 다를 수 있습니다."
  - "정확한 시간·경로·요금은 아래 길찾기 버튼으로 카카오맵에서 확인하세요."
- 필터: "통근 [전체|대중교통|자가용] [30|45|60|90분] 이내". 기본 `전체`(끄기).
  - 어림 범위의 **최솟값**이 기준 이하이면 보인다. 추정이 틀려 괜찮은 집이 숨겨지지 않게 하기 위해서다.
  - `commute: null` 거래는 숨기지 않는다.
  - 필터 옆에도 같은 ⓘ를 둔다.
- 직장이 없으면 통근 줄·링크·필터를 모두 숨긴다.

## 오류 처리
- 검색·좌표 API 실패는 화면을 막지 않는다. Cron은 `console.error`로 남기고 다음에 다시 한다.
- `JUSO_*` 키가 없으면 좌표 채우기를 건너뛰고, 설정 화면 직장 검색은 "주소 검색을 쓸 수 없습니다"를 보인다.

## 테스트 (가상 값)
- `utmkToWgs84`: 알려진 지점 두 곳(공개 좌표)으로 10m 이내.
- `straightKm`: 알려진 거리.
- `estimateCommute`: 경계값(0km, 1km, 30km), 5분 반올림, 최솟값 ≤ 최댓값.
- 단지 주소 문자열 만들기: 도로명 있음/없음, 부번 0, 리가 붙은 동.
- `geocodePending`(의존성 주입): 도로명 성공, 도로명 실패→지번 성공, 둘 다 없음→notfound, 네트워크 오류→pending 유지, 한 건 실패해도 계속, limit.
- 설정 스키마: workplaces 0·1개 허용, 2개 거부, 범위 밖 좌표 거부, 필드 없는 예전 설정 → `[]`.
- 통근 필터: 최솟값 기준, null 유지, 전체.
- 카카오맵 링크: 이름 정리, 좌표 순서.
